# 04. Copilot プロンプト集 (リファレンス / 二次フォールバック)

> **この資料は「手動コピペ用のプロンプト原文」です。**
> 通常は `docs/06-quickstart-flow.md` から **`sdd-guide` カスタムエージェント** を使ってください。
> このページは、(a) BYOK プレイグラウンドや Copilot CLI 等で手動コピペが必要なとき、(b) スラッシュコマンドが何を内部で書いているか確認したいときに参照します。

各セッションで Copilot Chat (または CLI) に貼って使うプロンプト集です。題材は架空の「マルチカメラ撮影プランナー」前提で書いています。

---

## 7.1 課題整理

```text
あなたは新しいツールのプロダクトマネージャーです。
題材は架空の「マルチカメラ撮影プランナー」で、複数台の IP 制御カメラを使う撮影現場を対象にします。
現状の課題は、設置前に「どのカメラが、どの被写体を、どの構図で撮るか」を視覚的に確認できず、
現場担当者の負担になっていることです。
このツールで解くべき課題を、次の 4 つの観点に分けて整理してください。

- ビジネス課題
- ユーザー課題
- UI 課題
- 技術課題

出力はそれぞれ 3 〜 5 個の箇条書きにしてください。
```

---

## 7.2 ユーザーストーリー生成

```text
以下の課題から、マルチカメラ撮影プランナーで実装すべきユーザーストーリーを 3 本作ってください。

課題:
- 複数カメラの配置と被写体の関係を、設置前に直感的に確認したい
- 現行ツールは設定値の入力中心で、意図した構図が撮れるかが分かりにくい
- 撮影ディレクターと現場オペレーターが、同じ画面を見ながら相談したい

出力フォーマット:
- ユーザー種別
- ユーザーストーリー (「〜として、〜したい。なぜなら〜」)
- 期待する価値
- 受け入れ条件 (3 〜 5 個)
- 今回のプロトタイプで扱う範囲
- 今回のプロトタイプで扱わない範囲
```

---

## 7.3 仕様化

```text
次のユーザーストーリーを、フロントエンドプロトタイプ用の仕様に落としてください。
ターゲットは Next.js (App Router) + TypeScript の SPA 風プロトタイプで、
本番 API 接続はせずモックデータで動かす前提です。

ユーザーストーリー:
「撮影ディレクターとして、ステージ上の被写体と複数カメラの配置を上面図で確認し、
各カメラがどの被写体をどの構図で撮るかを事前に確認したい。
それにより、現場設置前にカメラ台数・配置・構図の妥当性を判断できる。」

仕様に含めるもの:
- 画面一覧 (URL とその役割)
- 主要コンポーネント
- 入力項目
- 画面上の状態
- ユーザー操作
- 受け入れ条件
- エラー / 制約
- プロトタイプで省略してよいこと
```

---

## 7.4 実装計画化

```text
以下の仕様を、Next.js (App Router) + TypeScript のフロントエンドプロトタイプとして
実装する計画にしてください。本番 API 接続は不要、モックデータで構いません。
すでに prototype/lib/types.ts に Stage / Subject / Camera / OverheadCamera / Scene 型がある前提です。

出力してください:
- ファイル構成
- コンポーネント分割
- 状態管理の方針 (useState / useReducer / Context のどれを使うか)
- モックデータ構造
- 実装タスク (順序付きで 5 〜 8 個)
- 動作確認観点
- 30 分で作る場合に削る範囲
```

---

## 7.5 レビュー / 改善

```text
あなたはマルチカメラ撮影プランナーのビジネスレビュアー兼 UX レビュアーです。
以下のプロトタイプ仕様 / 画面挙動をレビューし、撮影現場で使うために不足している点を指摘してください。

観点:
- 初見ユーザーが理解できるか
- カメラと被写体の関係が直感的か
- 設置現場に持ち出せる情報が出ているか
- 3 時間ワークショップの範囲で改善できるか

出力フォーマット:
- 良い点 (3 個)
- 改善点 (3 〜 5 個)
- 優先度 (High / Medium / Low)
- 次のプロンプトで実装者に依頼する内容 (1 件分の具体指示)
```

## 7.6 (任意) コードレビュー

```text
あなたはシニアフロントエンドエンジニアです。
以下の React コンポーネントをレビューし、可読性・型安全性・状態管理の観点で
最大 3 つの改善提案をしてください。Next.js (App Router) + TypeScript 前提です。

[コードを貼る]

出力:
- 各提案について「何を / なぜ / どう直すか」を 3 行で。
- 必要なら最小限の diff を示すこと。
```

---

## プロンプト運用のコツ

- 1 プロンプト 1 要求。複数の依頼を 1 プロンプトに詰めない。
- 出力フォーマットを明示する。フォーマットがないと比較できない。
- レビュー観点はビジネスロールの言葉で書く。
- Copilot の出力をそのまま採用しない。必ずビジネスレビュアー / 開発レビュアーが目を通す。
