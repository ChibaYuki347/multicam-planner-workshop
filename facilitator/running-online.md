# 05. オンライン / ハイブリッド開催の注意点

## 開催形式の選び方

| 状況 | 推奨形式 |
|---|---|
| 全員フルリモート | フルオンライン |
| コアメンバーが同じ拠点 + 数名リモート | コア同室 + 残りオンライン |
| 拠点とリモートが半々 | フルオンラインを推奨 |

混在環境では、現地メンバーがマイクや画面共有を意識する負担が大きく、議論が止まりやすい。**人数が多くなるならオンラインに寄せる方が円滑** であることが多い。

## グループ分けのコツ

- グループは「現地グループ」と「リモートグループ」で分け、混ぜない。
- 1 グループは 4 〜 6 名が扱いやすい。
- 各グループに、ナビゲーター / ビジネスレビュアー / 開発レビュアーを 1 名ずつ置く。

## ツールの使い分け

| 用途 | ツール例 |
|---|---|
| 会議 | Web 会議ツール (画面共有 + ブレイクアウト) |
| 共同編集 | 共有ドキュメントツールでワークシートを開く |
| 仕様 / 計画の保存 | リポジトリ内の `exercises/` を都度コミット、もしくは共有ドキュメントに貼る |
| Copilot 実行 | ナビゲーターの IDE で画面共有 |

## オブザーバー席のすすめ

- 当日参加者の役割を「実行する人」と「観察する人」に分けると、進行と学びの両立がしやすい。
- 観察者は手を動かさず、終了 5 分前に「今日の学び」「自部署で試したいこと」を 1 〜 2 個発言してもらう。

## 録画と議事録

- 会議ツールで録画する場合、参加者全員に事前同意を取る。
- 議事録は「決定事項 / 次アクション / 持ち越し論点」の 3 セクションだけで十分。
- ユーザーストーリー、仕様、実装計画は Copilot 出力をそのまま `exercises/` に貼り、当日中にコミットすると後追いしやすい。
